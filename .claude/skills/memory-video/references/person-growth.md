# 人物成长线（任意命名人物）

把一个命名人物的照片，按**成长/人生弧线**生成短片。已验证 4 位人物的弧线骨架。

## 判断靠看，不靠算

「这一簇该不该出片」是一个**看照片**的判断。脚本给的 cos、相似度、pairwise 全都是**注意力索引**——它们告诉你先看哪里，不能替你下结论。

这个库里，任何单一数值阈值都会两头出错，因为：

| 现象 | 后果 |
|------|------|
| **幼年 vs 成年**：同一个人 3 岁和 30 岁的脸差别极大 | 阈值低 → 把成长线自己判成「两个人」 |
| **相似亲属**：母女、姐妹在 face space 里本来就重叠 | 阈值高 → 把混合簇判成「一个人」 |
| **遮挡**：口罩/墨镜/帽子/侧脸/小脸让 embedding 饱和 | 给出虚高相似度，甚至石像、海报、面雕都能自聚成簇并 cos 0.8+ |
| **合影**：一张照片多张脸揉进同一 embedding | 成为混合簇的种子 |

真正好用的判据只有一条：**把照片摊开，看一眼**。一眼看不出是不是同一个人，就再靠近一点看脸；还看不出，去看和已知人物的并排对照。

## 核验素材包

```bash
node scripts/person-contact-sheet.cjs <personId> [--per-year 4] [--list]
```

产出三张表和一段摘要（摘要里**只有事实**：年份分布、独立拍摄日、原图可用性、同框信号）：

| 表 | 回答的问题 |
|----|-----------|
| `contact.jpg` | 整图按年摊开——**这是一个人吗？这些年有变化吗？** |
| `faces.jpg` | 人脸特写——拿不准时脸对脸细看 |
| `vs-named.jpg` | 与全部命名人物并排——**这簇是不是某个已出片人物的拆分/重复？** |

摘要里的「同框信号」（这张照片同时挂着别的 person）是合影混合簇最快的线索：合影是这个库里脏簇的最大来源。

### 怎么读这些图

Claude 自己 `Read` 即可。若要用 qwen vision，注意 **`qwen vision` 默认打印的是思考链而不是答案**——必须走结构化输出取 `content`：

```bash
qwen vision --json -t 4000 -i vs-named.jpg "<问题>" | jq -r '.choices[0].message.content'
```

`content` 为空或 `finish_reason=length` = 思考把 token 吃光了，换更小的问题重问。**一图一问**效果最好（「这张图里出现了几张不同的面孔？」比「请分析这张对照图并给出完整身份结论」可靠得多）。

## 三种结局

看完图之后，只有三种结果，都要**说清看到了什么**：

1. **出片**——是真实的人，素材撑得起一条线
2. **这是已出片人物的碎片**——看出来了它其实是某人的拆分簇或合影混合 → 不出片，登记 `video.skipPersonIds`
3. **这不是一个人 / 素材不够**——合影混合、非人脸误检、或照片全挤在一两个场景 → 不出片，登记 `video.skipPersonIds`

「看得出时间在走」是成长线的门槛：如果 contact.jpg 翻下来所有照片都像同一天同一场景，那是连拍，不是成长线。

## 选片

出片确认后：

1. **去连拍**：每 burst 留代表（`is_burst_representative=1` 优先，否则最高美学分）
2. **按维度选片**：
   - 成长线（孩子）：按**年**分组，每年美学 + 场景多样选 3-4 张
   - 人生弧线（成人）：按**人生阶段**挑（少女/相恋/新婚/孕育/为母），不机械按年——13 年跨度按年会出 45 张太多，要精选到 ~16 张
3. **cos 在这里才派上用场**：作为**排序依据**挑每年最像本人的几张（同一年的照片，cos 高的更可能是正面清晰照）。它不是过滤器，是排序器。

## 叙事骨架（LLM 提案，不硬编码）

引擎**不预设骨架**，由 LLM 读选片的 narrative 提案章节。已验证的范式：

| 类型 | 骨架 | 实例 |
|------|------|------|
| 孩子 | **年龄里程碑**：稚嫩→好奇→欢腾→远行 | 合一（2022-2026，首尾「睁眼的小→远方的远」）|
| 成人（女） | **人生阶段**：少女→相恋→新婚→孕育→为母 | 翁雪珂（2013-2026，首尾「独自远行→牵手看世界」）|
| 成人（男） | **人生阶段**：初见→立身→远行→成家→为父 | 赵桂雄（2013-2026，首尾「少年独行→抱你重走世界」）|

关键：**弧线字幕推进情绪不描述画面**，word 是成长/人生锚点不是地名。

## 婴儿期 gap（孩子主题）

孩子主题有**跨年龄 cos 衰减**：centroid 被近期照片主导（赵合一 2024 占 577/1310 张），婴儿脸与当前质心天然不似。
- 实测：赵合一 2019-2021（0-2 岁）cos≥0.5 池 = **0 张**，2022 也仅 1 张
- **靠看解决**：婴儿照大概率就是本人（家拍婴儿照的语境摆在那里），翻 contact.jpg 确认画面语境即可，不需要靠 cos 证明
- **替代**：跳过婴儿期从 3 岁起（成长线缺襁褓但叙事链路完整）

成人主题无此问题（翁雪珂 13 年 cos 全 ≥0.5）。

## 跨视频去重（亲子照陷阱）

一张亲子照里**母亲和孩子都被识别**，会同时进两人的候选池。
- 实例：`57f52276`（红杉林）、`7d0abe0d`（春节心形）同时在赵合一 + 翁雪珂池
- **正式版**：建 `video_usages(photo_id, video_id, theme, created_at)` 表，召回时 JOIN 排除近 N 周用过的照片。同一照片跨主题可复用，但短期不重推。
- 选片时一并排除 **videos 表 completed 的 themeKey 已用素材**

## persons 表

```sql
SELECT id, name, member_count FROM persons
WHERE name IS NOT NULL AND name != '' ORDER BY member_count DESC;
```

当前命名人物：赵合一(1322) / 翁雪珂(870) / 赵桂雄(144) / 王语晨(142) / 徐群仙(137) / 赵锡根(93) / 赵狄苏(27)。

> `赵狄苏` 的 name 字段带一个真实控制字符（`"\u0010赵狄苏"`，终端显示成 `^P`）。它进 SVG 会让 librsvg 报「Input buffer has corrupt header」并指不到元凶——渲染脚本必须消毒（`person-contact-sheet.cjs` 的 `xmlSafe` 是范例）。

跨度查询（判断适合哪种骨架）：

```sql
SELECT p.name, MIN(ph.taken_at), MAX(ph.taken_at), COUNT(DISTINCT ph.id)
FROM persons p JOIN faces f ON f.person_id=p.id JOIN photos ph ON ph.id=f.photo_id
WHERE p.name=? GROUP BY p.id;
```

## 未命名聚类（name=null）同样能出片

`daily-video` 发现逻辑会给 **name=null 的聚类**出片。区别只在呈现：
- **标题策略**：用描述性标题（如「父与子 · 八年时光（2018–2026）」），不用 `<名字> · 成长线`；视频内 CQ_TITLE 用短词
- **叙事骨架**：与命名成人相同，LLM 按 narrative 提案人生阶段，不机械按年
- 身份判断流程与命名人物完全一致：摊开看
